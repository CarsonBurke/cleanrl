# Independent nonlinear chord-JVP contract review

Static review only. No model/test execution or queue submissions. No original source edits. Numerical success remains pending.

## Verdict

No blocking implementation defect found. The test is a meaningful independent finite-difference check of the real nonlinear actor chord JVP, within a declared3% vector-error tolerance. It does not merely compare two automatic derivatives. It covers both Adam/Anvil saved policies at4M and8M, and their actual first-update and complete-update endpoint directions. The scope is the ambient parameter chord at the old actor, not a retracted-path derivative or a finite-return oracle.

## Chord/source reconstruction

`reconstruct_banks` enforces matching global steps, complete sequential update count from epochs/minibatches, exact parameter-key sets, shapes and cumulative replay agreement within2e-5. The first actor bank is old FP32 weights plus the first saved retracted FP32 parameter delta, and its chord is that reconstructed bank minus old. The endpoint bank uses the exact saved `model_after_update` tensors, not replayed deltas, and its chord is endpoint minus old. Actor and critic snapshot loading is strict; old critic evaluation remains intentionally unchanged.

The numerical test checks cumulative reconstruction tolerance and exercises real motion in all six gate/up/down banks and readout/head. These are meaningful guards against a bias-only witness. First-bank reconstruction retains an explicitly acknowledged subtract/add roundoff; the trace does not provide a separate exact first-bank state. Unit-axis norm errors are reported by the helper but not separately asserted by this test.

One coverage limitation: both automatic JVP and finite differences consume the SAME helper-returned chords. A future reconstruction bug that consistently supplied a wrong chord could pass this JVP test. Independent direct assertions against raw snapshot first delta and saved exact endpoint would close that gap. Current source inspection validates those definitions, but the finite-difference agreement alone does not independently validate them.

## Independent finite differences and wrong-JVP sensitivity

The reference primal path is a separate compiled `functional_call` forward with no JVP, backward or analytical Jacobian. It evaluates old plus/minus h times the actual chord and promotes outputs unchanged to FP64 before subtraction. It checks old-primal agreement, so base-policy disagreement cannot silently become derivative evidence. It also follows the SAME ambient path as `compiled_directional`, avoiding a mistaken comparison with sphere-retracted perturbations.

A sign error, missing consequential hidden derivative or substantial scale error in the JVP would generally disagree with the centered primal difference. Requiring at least two adjacent h values to meet all criteria is stronger than choosing one favorable crossing of truncation error and roundoff. It is not a proof that arbitrary adversarial errors or sub3% scale errors are detected, and the sweep has no assertion of a mathematical second-order convergence rate.

Thresholds are strict relative vector error<.03 and cosine>.999, together with effective rounded parameter-chord error<.02 and heuristic output-rounding telemetry<.03. Their conjunction is reasonable for a finite-precision numerical gate; it must not be promoted to exact equality. A vector error below3% can still produce a large relative error in a nearly cancelling score-weighted scalar PG. Physical scalar margins/uncertainty remain separate.

Parameter rounding is measured by comparing the actual centered FP32 parameter displacement to the intended chord. Output rounding is only a scale heuristic based on16*eps*output magnitude/h, explicitly labeled nonrigorous. It cannot upper-bound all compiled matrix-accumulation, cancellation or nonlinear-normalization errors. Since it is an additional gate rather than an allowance added to the error threshold, it cannot excuse arbitrarily inaccurate finite differences. Very small derivative signal may legitimately fail this test without demonstrating a wrong JVP.

## State, buffers and provenance

The actor parameters are private loaded snapshot data; `functional_call` substitutes banks without optimizer steps or retraction. The endpoint stays in a parameter bank and is not loaded into the live agent, preserving the old critic for the full diagnostic. The primal finite-difference outputs are cloned; automatic JVP outputs are converted to FP64 before each chord's comparisons. CUDA graphs are disabled, limiting reused-output-buffer concerns. No environment trajectory or benchmark score is generated by this numerical contract.

The test records snapshot, trace and key transitive source SHA256s and checks snapshot/trace immutability at completion. This records exactly what was tested but is NOT itself an external canonical hash pin: a changed file present before the test would simply get a new recorded hash. Harness/manifest reconciliation must tie these hashes to the intended executed frozen artifacts. Source hashes are recorded but not rechecked at the end; no concurrent mutation should be assumed safe.

## Interpretation gate

A queued pass can support the local nonlinear actor JVP at these saved states/chords within the printed tolerances. It does not validate unseen states, the physical score law, terminal-value correctness, all-time PG Monte Carlo precision, endpoint return improvement or benchmark causality. Retain the complete sweep/provenance rather than recording only the Boolean test result.
